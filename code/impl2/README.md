# Second implementation

The first level and the second level of the paper are computed by `tfilter` and `tdeep` (Rust, `code/impl1/rust/`). This directory holds a second implementation of both levels, `vlevel1` and `vkill` (Rust, crate `tverify`), and the test program `vtest` (Section 6.5 of the paper). It was written from a written description of the arguments of Sections 3 to 5 and from the data files, without reading the source of the first. It writes no certificates: its verdicts are checked by rerunning it.

|                      | first implementation (`code/impl1/rust`)                                                                                                                                   | second implementation (this directory)                                                                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| interval arithmetic  | IEEE 754 binary64, each operation widened by one ulp (`iv.rs`, `ivt.rs`)                                                                                                   | its own, the same model (`iv.rs`)                                                                                                                                                       |
| elementary functions | Cody and Waite reduction by `π/2` in three parts, Taylor polynomials of degree 20 and 21, `arctan` from a table of `arctan(j/8)` (`rtrig.rs`); MPFR as an optional backend | tables of `cos(k/64)`, `sin(k/64)`, `arctan(k/64)` enclosed with MPFR, Taylor polynomials with Lagrange remainders (`elem.rs`, `mp.rs`)                                                 |
| contractors          | the relations of Section 5.3, natural interval extensions                                                                                                                  | mean value forms by automatic differentiation (`ad.rs`), more relation families per face: every triple of other corners of a hexagon, pentagon splittings along a diagonal (`faces.rs`) |
| gluing, Pair, Local  | `local.rs`                                                                                                                                                                 | its own (`glue.rs`)                                                                                                                                                                     |
| further refutation   |                                                                                                                                                                            | Edge: the enclosure of each edge length against `2 sin(d/2)`                                                                                                                            |
| first level          | `tfilter`: the rows of Section 5.2                                                                                                                                         | `vlevel1`: the same rows and the rows "the corners of an `m`-gon sum to at least `(m - 2)π`" (`level1.rs`)                                                                              |
| output               | a search tree per graph, replayed by `tdeep --replayfile`                                                                                                                  | a verdict line per graph                                                                                                                                                                |

The constants of `src/consts.rs` are checked by `consts_check.gp` (PARI/GP, 200 digits; output `consts_check.out`; rerun by the job `gp` of the continuous integration).

## What each claim rests on

Every check runs from the repository root through `code/rerun.sh NAME` (build first with `code/rerun.sh build_impl2`). Times are wall clock on an AMD Ryzen 9 5900X while other work was running.

`out/residue_verdicts.txt` names the builds of `vkill` that made the recorded runs: `bin_v2`, `bin_v3`, `bin_v5`, `bin_v6` are successive versions, each adding options (`--incr`, `--dropfam`, `--part`) without changing the search for a given set of options. The `vkill` of this directory reproduces the node count of every one of their 54 runs. `out/fp_verdicts.txt` lists the 156 free-point cases with the verdict of `vkill` and the passes of `tdeep` that killed the same case; `out/map_*.txt` are the index maps between the level-2 input files and the case tags.

## Rerunning

```
code/rerun.sh build_impl2 test_impl2 sample_kill nolocal vtest_c1_edges vtest_c3_edges vtest_c1_vertex vtest_c3_vertex
JOBS=4 code/rerun.sh residue_a residue_b residue_c residue_d residue_e
```

The bulk passes need the level-2 input files of the release assets (`code/impl1/fetch_assets.sh`): `vkill ASSETS/inputs/in_k0_0.pc --iso 0 --targets data/tie_targets.txt --local --pair --edge --nodes 30000 --maxsec 5`, and so on for each input file. They are not rerun by the continuous integration (about 14 core hours).
