# Third-party code

## plantri 5.8 (programs, not included)

The enumeration (Section 7.2 of the paper) uses plantri 5.8 by G. Brinkmann and B. D. McKay (https://users.cecs.anu.edu.au/~bdm/plantri/, Apache License 2.0). No source file of plantri is in this repository: `code/impl1/enum/build_plantri.sh` downloads the tarball `plantri58.tar.gz`, checks its sha256 (e78a944116fec9f2c9f5e484206276cc2b0043bae803e9815f4b2683614629b8) and compiles plantri with the output filter written for this work, `code/impl1/enum/plantri_md5.c` (maximum degree at most 5), through plantri's plugin interface (`-DPLUGIN=...`, plantri-guide.txt). `code/impl1/enum/plantri-guide.txt` is the guide of plantri 5.8, unchanged.

# Third-party Lean code

## Energy-Minimization-8-Points (library `VendorEM8`, directory `Tammes15/Vendor/EM8/`)

Source: github.com/lukasliehr/Energy-Minimization-8-Points, commit 50d14bc06bd41f61573eb6a36eedb8d00759af8f, directory `LeanCode/LargeS/Lean_Code`. It is the Lean 4 formalization accompanying Kryvonos, Liehr and Taylor, arXiv 2609.22077, whose large s part proves the Tammes theorem for eight points with rigidity (`SquareAntiprismVerification.eight_point_best_packing_rigidity` in `BestPacking.lean`, here `Tammes15.Vendor.EM8.SquareAntiprismVerification.eight_point_best_packing_rigidity` in `Tammes15.Vendor.EM8.BestPacking`). The repository carries no licence file at that commit. Its files are included here with credit to their authors; the Apache 2.0 licence of this package covers the rest of the package, not these files.

Files taken: the 140 modules reachable by imports from `BestPacking.lean`, listed in import order in `code/vendor/vendor_order.txt`. Each file `Tammes15/Vendor/EM8/<M>.lean` is `LeanCode/LargeS/Lean_Code/<M>.lean` of the source. The copy is made by `code/vendor/vendor.sh` from a clone at the commit above, so it can be redone and compared with the source: `code/vendor/regen_check.sh` regenerates the 140 files and finds them identical to those of `Tammes15/Vendor/EM8` (`code/vendor/regen_check.out`).

Changes, all made by `vendor.sh`:

1. Every file starts with three comment lines naming the source repository, the commit, the source path and the paper.
2. Module names: the prefix `Lean_Code` of the imports is renamed `Tammes15.Vendor.EM8` (`import Lean_Code.X` becomes `import Tammes15.Vendor.EM8.X`), so the modules are `Tammes15.Vendor.EM8.X`.
3. Declaration names: the lines `namespace SquareAntiprismVerification` and `end SquareAntiprismVerification` that enclose the declarations of each file become `namespace Tammes15.Vendor.EM8.SquareAntiprismVerification` and `end Tammes15.Vendor.EM8.SquareAntiprismVerification`, so a declaration `SquareAntiprismVerification.x` of the source (its sub-namespaces included) is `Tammes15.Vendor.EM8.SquareAntiprismVerification.x` here. The source declares nothing outside that namespace, so no declaration keeps a root-level name or a Mathlib namespace (`code/vendor/em8_names.out`). References inside the files are unchanged: they resolve through the enclosing namespace.
4. `Tammes15/Vendor/EM8/SolidAngleDerivative.lean` and `Tammes15/Vendor/EM8/CycleSeparationValue.lean`: one line `set_option synthInstance.maxHeartbeats 200000` before `noncomputable section`, marked by a comment `-- tammes-15 port change`. On Lean v4.34.1 with Mathlib d13f23b7 (the toolchain of this package; the source used Lean v4.33.0 with Mathlib db584cd6) the instance search for `ContinuousSMul ℝ ℝ³` times out at the default limit of 20000 heartbeats (in `SolidAngleDerivative`, and in `CycleSeparationValue` at lines 28 and 51 of the source). No proof is changed.
5. Build options (`lakefile.toml`, library `VendorEM8`): `autoImplicit` and `relaxedAutoImplicit` are set to true, Lean's defaults, under which the source was written; the rest of this package sets them to false.
6. Hand changes, 31 in 12 files, listed in `code/vendor/handfix.tsv` (module, line of the source, the source line, its replacement, the reason) and applied by `code/vendor/handfix.pl`; in its file each one follows a comment line `-- tammes-15 port change:` giving its reason. The face chain of the source that ends in `ContactBoundaryCycle.strict_support_of_weak_support` (module `BoundaryFaceSupport`) uses the bound `c ≤ aInf` only through `irreducible_component_two_connected`: deleting one vertex leaves every nontrivial contact component connected (`code/vendor/aInf_uses.out`). The port names this property `ContactTwoConnected Y c` and proves it from the bound (`contactTwoConnected_of_aInf`, both added to `ContactComponents`). The 11 lemmas of the chain take `hconn : ContactTwoConnected Y c` in place of `hcupper : c ≤ aInf`, 17 calls pass it on, and `irreducible_boundary_support` supplies it from `hcupper` by `contactTwoConnected_of_aInf`, so its statement is unchanged. The last hand change is in `BoundaryPolygons`: `length_le_eight_of_support`, whose bound 8 is the number of points, binds its variables at `Fin 8` itself instead of taking them from its section, with the same type. With these changes the chain applies to fifteen points, where the package proves the two-connectivity directly (Corollary A.6 of the paper).
7. Number of points: in every declaration outside the list `code/vendor/keep8.tsv`, `Fin 8` is written `Fin nPts`, where `nPts` is an implicit variable bound automatically (change 5); the rewriting is done by `code/vendor/probe_mix.pl`. The list holds the 122 declarations that need eight points, either in their own proof or through a listed declaration they use at `Fin 8`. It was computed by `code/vendor/generalize.sh`, which compiles each file in import order with every declaration generalized except those already listed, adds each declaration with an error to the list, and compiles the file again until it builds; `code/vendor/generalize.out` gives the result per file. In this copy 48 files contain `Fin nPts`, 323 times. At `nPts = 8`, a generalized declaration has the type of the source declaration. The eight-point theorem is on the list, so its statement is the one of the source, and its proof still uses only the standard axioms (`code/lean/axioms.lean`, output in `code/lean/check.out`).

Nothing else differs from the source. Take each file, remove its first three lines, write `Fin 8` back for `Fin nPts` (the source has no `nPts`), undo the hand changes of change 6, and undo the renamings of changes 2 and 3. Its `diff` against the source is then empty, except for the two marked lines of change 4 (`code/vendor/vendor_check.sh`, output `code/vendor/vendor_check.out`).
